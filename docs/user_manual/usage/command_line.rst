.. _usage:

Usage
#####

The ``discovery-server`` tool is set up from a single XML configuration file passed as a command-line argument.
The binary is named after the pattern ``discovery-server-X.X.X(d)``, where ``X.X.X`` is the version number and the
optional *d* denotes a debug build.

To have the tool accessible in the terminal session it is necessary to source the setup file generated by colcon.

-   **Linux**

    .. code-block:: bash

        $ source <path/to/discovery-server-ws>/discovery-server-ws/install/setup.bash
        $ discovery-server-X.X.X(d) -c config_file.xml

-   **Windows**

    .. code-block:: batch

        > . <path\to\discovery-server-ws>\discovery-server-ws\install\setup.bat
        > discovery-server-X.X.X(d).exe -c config_file.xml

The tool accepts the following arguments:

.. list-table::
    :header-rows: 1

    *   - Argument
        - Description
    *   - :class:`-h` |br| :class:`--help`
        - Produce help message.
    *   - :class:`-c` |br| :class:`--config-file`
        - Mandatory path to the XML configuration file that describes the scenario to deploy.
    *   - :class:`-o` |br| :class:`--output-file`
        - File where the resulting snapshots are written.
          If not specified, they are written in the file declared in the ``snapshots`` tag of the configuration file.
    *   - :class:`-s` |br| :class:`--disabled-shared-memory`
        - Disable the shared memory transport.
          The test suite uses it to run every scenario with and without shared memory.

The structure of the configuration file is described in :ref:`config_files`, and complete examples are available in
:ref:`basic_config_file` and :ref:`advanced_config_file`.

By default the tool runs until the user shuts it down.
Configuration files used as test cases set :code:`user_shutdown="false"` in their ``DS`` tag so that the tool
finishes as soon as the last event of the scenario has taken place, which is the behavior the test suite relies on.
Refer to :ref:`test_suite` to run the scenarios as an automated test suite instead of launching them by hand.
