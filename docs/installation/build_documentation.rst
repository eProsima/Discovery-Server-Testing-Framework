Building the documentation
##########################

The sources of this documentation live in the ``docs`` directory of the
`Discovery Server testing framework repository <https://github.com/eProsima/Discovery-Server-Testing-Framework>`__,
next to the sources of the framework itself.
They are rendered with Sphinx_, and the build is driven by the same CMake project that builds the
``discovery-server`` tool, so the documentation is generated by enabling the :class:`BUILD_DOCS` option described in
:ref:`cmake_options`.

.. contents::
    :local:
    :backlinks: none
    :depth: 2

Requirements
************

The documentation build requires Python3_ and the packages listed in ``docs/requirements.txt``.
Installing them in a virtual environment keeps them isolated from the system packages:

.. code-block:: bash

    python3 -m venv docs-venv
    source docs-venv/bin/activate
    pip3 install -r <path-to-repository>/docs/requirements.txt

The spell checker relies on the ``enchant`` library, which is not a Python package and must be installed with the
package manager of the appropriate Linux distribution.
For example, on Ubuntu use the command:

.. code-block:: bash

    sudo apt install libenchant-2-2

Building
********

Configure the project with :class:`BUILD_DOCS` set to ``ON`` and build it as usual.
With colcon_:

.. code-block:: bash

    $ colcon build --base-paths src \
            --packages-up-to discovery-server \
            --cmake-args -DTHIRDPARTY=ON -DCOMPILE_TOOLS=ON -DINSTALL_TOOLS=ON \
                    -DBUILD_DOCS=ON

The generated HTML is written to the ``docs/html`` directory of the build tree, with ``index.html`` as entry point,
and it is copied to ``share/doc/discovery-server/html`` on installation.

CMake locates the ``sphinx-build`` executable next to the Python3_ interpreter it found, which is the right one when
the requirements were installed in an active virtual environment.
If a different one has to be used, point CMake to it explicitly:

.. code-block:: bash

    -DSPHINX_BUILD_EXECUTABLE=<path-to-sphinx-build>

Formats other than HTML are produced by selecting a different Sphinx_ builder with the :class:`DOCS_BUILDER` option,
for instance:

.. code-block:: bash

    -DBUILD_DOCS=ON -DDOCS_BUILDER=singlehtml

Testing the documentation
*************************

Two checks are registered with CTest when the documentation is built as part of a testing build: the RST sources
must comply with the style guidelines, and the text must be free of spelling errors.
Both are run with:

.. code-block:: bash

    $ ctest -R documentation

Words that the spell checker does not know, such as product or class names, are declared in
``docs/spelling_wordlist.txt``.

Building the documentation alone
********************************

Working on the documentation does not require the framework and its dependencies to be built.
The ``docs`` directory is a CMake project of its own, so it can be configured directly:

.. code-block:: bash

    $ cmake -S <path-to-repository>/docs -B build-docs
    $ cmake --build build-docs
    $ ctest --test-dir build-docs

The :class:`DOCS_BUILDER` option applies to this project as well, so any format supported by Sphinx_ can be
rendered this way.
